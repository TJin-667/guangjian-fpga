# 一组可迁移的真实输入与最终f09离线复算

选用已正式核验的旧组`sample004_g1793337600415116700`，不是用户要求跳过的10/30晚间新组。全图ROI `[576,160,864,864]`，格式49，400/800、gain16=16、LED128，真实8正式帧；ROI准备帧没有混入。

`sample004_gray49/CASE.json`逐帧提供可迁移相对路径、槽号、实际参数和身份。`frames/01..08`保存原灰度PNG/GRAY8/SAT1、原格式49载荷、mask、metadata包、原归档record。格式49按8灰度像素+1个SAT字节交错，不是整幅灰度后简单拼接SAT。`fusion/`为真实R32和原融合结果；`expected/`为实际窗口保存的最终10数组、完整复检、评分及图。`source_job/`和`provenance/`保留来源与计时，原绝对路径只作历史身份记录，复算选用CASE中的相对路径。

## 可在另一位置执行的命令

推荐Python3.11，本次已验证环境Python3.11.4、NumPy1.26.4、OpenCV-headless4.10.0.84、Pillow12.3.0。其他Python版本需确认这些依赖的支持范围。建议在新虚拟环境安装锁定版本，写作任务不必更改现有环境；本次没有另做一次全新环境安装测试。

```text
python -m pip install -r replay_requirements.txt
python -B replay_case.py --out <包目录之外的一个尚不存在的新输出目录>
```

上述命令在交接包根运行。必须取齐`replay_capsule/`和本cases目录。程序只从包内读取数据与原数值依赖，禁止socket/子进程，输出到新目录；不依赖原仓库路径、YMW的E盘或板卡。

成功输出`PASS_RELOCATABLE_FROZEN_REPLAY`：重算灰度输入的精确H2/valid/MaxAbs，比较真实R32及选中gray，然后执行原f09 API，比较10项正式数组、完整复检证据和分数。它验证数学复算，**不是再次拍照、当前硬件状态或原UDP全部包的重新验收**。本组无同帧RGB，不能独立证明RGB→gray的物理转换。

原算法源码/参数按SHA保存，不调整门槛、不覆写上游绑定；只在新的封装中从八平面构造同一数学上下文。旧源码中没有调用到的E盘常量保留原样，外部文件访问审计会阻止实际依赖它们。原record和原OUTPUT_MANIFEST描述的是E盘原完整归档，当前子集由本目录MANIFEST及总包MANIFEST分别封印。

该单组用于复现和报告图，不构成独立准确率样本或新性能测量。复算结果与现有实板期望相同不等于划痕人工真值全部正确。
