# 可复用的主机分段计时与证据范围模板

这是普通比赛协作技能包，不是PYNQ Overlay/Skill，不申请PYNQ专属额外加分。

## 适用范围

Python主机程序中的采集、RPC、DMA服务等待、CPU参考、后处理和导出分段。独立`host_timing.py`只依赖Python标准库，不需要光鉴板卡、路径、numpy或OpenCV。换题目可把自己的函数交给`Ledger.wrap()`或放入`span()`。

```powershell
python example.py --out profile_example.json
```

示例仅散列内存中的固定字符串，演示记录契约，不是光鉴或FPGA性能数据。

## 从项目中总结的规则

1. 主机`perf_counter_ns`给出墙钟区间，RPC还包含网络、重试与调度；不能写成器件周期。
2. 父阶段包含子阶段，嵌套时间不能直接相加。异常阶段也要保存，不能只留下成功耗时。
3. 一次逻辑RPC的字节数不能代替真实收发计数；重试后的实际字节另从传输器取得。
4. 比较算法或硬件时固定输入字节、ROI和参数；不同次拍摄不是同输入。
5. 先完成完整审计才谈重复证据复用；缓存摘要相同还不够，必须与原始证据绑定，防止误换来源/数组。光鉴的SDK/H2缓存适配是项目专用实现，不宣称该部分可直接换板即用。
6. 未测字段用null或明确未完成，不能把零当作未测值，更不能从主机服务时延推导FPGA纯计算加速比。

## 已验证的效果与失效条件

光鉴中，计时包装真实SDK的软件peer49/50流程后，原生图与融合状态保持一致；失败、嵌套、重试计数契约由测试覆盖。实际004归档的复用优化和PC参考记录见本交付results，不把它当成其它题目的性能保证。

如果设备异步执行，函数返回可能只是接受任务，必须把完成等待另计；本工具不会自动知道DMA/FPGA真正完成时间。`Ledger`为单线程/单任务记录器，多线程应各自建实例后按任务ID汇总。需要器件周期、功耗和持续吞吐时必须增加对应的设备测量，不能由本模板代替。

模板源于本次开发的`final_system_20261029/performance.py`通用Ledger部分；保留项目验证结果和错误分支作为证据。未在未知第三方硬件上做部署测试。
