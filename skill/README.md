# 主机分段计时与证据范围 Skill

本技能从光鉴的性能核对与交接优化中提炼，适用于 Python 同步任务的主机墙钟计时。它只使用标准库，可用于其它项目的函数、RPC 等待、CPU 参考、后处理和导出记录，不依赖光鉴板卡、路径或第三方计算库。

## 独立使用

在仓库根目录运行，输出目录应已存在，结果文件选择新名称：

```text
python -B skill/host_timing/example.py --out timing_example.json
```

示例只散列内存中的固定字符串。输出 `status=EXAMPLE_ONLY_NOT_HARDWARE`、`physical_hardware=false`、四个包含式区间；三个子区间属于同一父区间。结果不是系统性能或 FPGA 测量。

将 `host_timing.py` 放入自己的 Python 模块搜索路径，使用 `Ledger.span()` 包装区间，或用 `Ledger.wrap()` 包装同步函数，再调用 `save()` 保存记录。`rpc()` 记录逻辑 RPC 的耗时和字节，`capture_cost()` 可记录传输器给出的实际收发计数。当前实现为单线程/单任务记录器。

## 来自实际开发的经验

光鉴最初完整任务中 PL 协作更慢，进一步分析必须分开采集、通信、审计、交接和完整导出。软件区间优化经过固定同输入比较后，才可以主张相应阶段的收益。[验证说明](../docs/validation.md)

1. `perf_counter_ns` 是主机墙钟；RPC 可包含网络、重试和调度，不能称为器件周期。
2. 父区间包含子区间，不能直接相加。异常区间也保存，不能仅留下成功耗时。
3. 逻辑 RPC 字节与传输器实际收发字节不同，重试成本应另计。
4. 同输入比较须固定原始字节、ROI、参数和核验范围；不同次拍摄不能当成同输入。
5. 缓存复用须绑定原始证据、源版本和数组，不能只比较一个摘要后默认一致。
6. 未测字段留空或 null，不能用零替代，也不能从主机时延推算纯 FPGA 加速。

## 验证与边界

源 `host_timing.py`、`example.py` 从固定写作包按原字节复制，本次不改代码。既有项目记录包含 SDK 软件 peer、异常、嵌套和重试契约验证；它们不是未知第三方设备上的部署结果。本次交付另保存独立示例的真实运行回执，标为示例。

设备异步执行时，函数返回可能只是受理，必须显式等待并记录完成；本工具不感知 DMA 或 FPGA 完成。多线程各用一个 Ledger 后按任务身份汇总。设备周期、功耗和持续吞吐需要相应设备测量。

原始说明保存在 [source_readme.md](host_timing/source_readme.md)；其中项目验证引用属于源资料背景，当前结果与入口以本技能说明及[证据索引](../report/evidence_index.md)为准。本技能为普通可复用计时工具，不是 PYNQ Overlay 或额外加分 Skill。
