## 已处理的问题

- 把融合放在独立CPU子进程，避免07控制器与XDL同名Python模块相互覆盖；子进程可取消，日志写文件避免管道阻塞。
- 只有人工确认后才能发实际采集命令；预检、离线导入、窗口打开都不连接板卡。新来源/新轮次清除旧成功状态和勾选。
- 原08固定600行的预检不能直接改曝光后复用；09新增独立适配器并重新绑定07本轮锁定结果，同一参数重新拍四图。
- 四方向始终同样件、ROI、mask和曝光；逐帧核对实际参数、读回、身份、原像素、H1/H2。合法计数回绕按协议位宽处理。
- 融合前先验证封存输入库存，拒绝截断或混入另一光向的记录。共用mask为0/1；unknown与固定几何分开。
- 所有失败/取消保留已采原图和成本；在采集器有效时finally尝试关灯。关灯未确认时不显示普通完成。
- ZIP导入同时检查Windows的原始成员名，避免zipfile自动规范化后漏掉反斜杠；拒绝越界、重复、保留设备名、符号链接、加密和超限库存。
- B1没有质量权重输入，NPZ沿用原发布约定保存空的quality_q8；M1保存4方向Q8数组。不能为了“字段都有”改变参考数组口径。
- 图像查看异常会禁用开始、保留日志并继续轮询；不会让失效的轮廓预览继续采集。
- 原始入口/bit/依赖按SHA核对，09安装器只增加自己的目录和ASCII/CRLF启动脚本，拒绝覆盖已安装09。
