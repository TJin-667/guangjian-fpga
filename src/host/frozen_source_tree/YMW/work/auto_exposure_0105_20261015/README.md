# BX72电脑端自动曝光实验程序

适配当前0x0105 LAB bit。固定CH1上方、LED128、增益1×，从600行开始，在400/500/600/700行中按XDL现有规则选择、重新拍摄确认、锁定或明确停止。新增中文窗口，采集和计算在工作线程执行，主线程显示来源轮廓、新图、指标、动作和结果。

打开窗口只检查本地文件。本人检查本轮轮廓和摆放、勾选确认并点击“开始自动曝光”之后，程序才访问板卡。助手没有运行实板、烧写bit或更改网络。

## 本机使用

入口：`C:/BX72_0105_LAB/07_auto_exposure.cmd`。当前r3安装在同目录的`auto_exposure_r3/`，首版`auto_exposure/`与r2保留作回退；原预览、02～06、冻结runtime及bit保持原样。

1. 先放好工件。若换板、移动相机/灯位/工件或重新上电，先运行02重新定位，再运行03检查实际裁剪。02时输入真实样件编号。
2. 关闭预览和其他采集窗口；保持板卡供电，由本人手动断开VPN。
3. 双击07。窗口默认载入最新02目录，显示样件编号、ROI和轮廓图。最新02失败时会拒绝，不回退到旧轮廓。
4. 检查整板和周边都保留，确认仍是同一块板、同一位置，再勾选并开始。也可“选择完整图目录”明确选择对应轮次。
5. 一轮中保持摆放不动。程序显示新图、曝光、板面指标和下一动作。需要中止时点击“停止并关灯”；关闭窗口也会先请求停止并保存。
6. 结束后保存`results/auto_exposure_样件_时间_随机号.zip`、`.zip.sha256`和`.zip.receipt.json`，恢复VPN后把ZIP交给助手核验。若压缩失败，可点“打开本轮结果”找到保留的原始目录。

默认最新来源曾是sample002的17:37完整图。它只是本地默认选择，不代表当前实物位置仍有效；每次运行由本人确认。样件编号从完整图继承，换板应重新02，避免只改名字却沿用上一块板的mask。

## 结果怎么理解

- 参数已锁定：同一曝光的独立新观测满足当前成像和稳定性规则。不是缺陷判定，也不是全局最佳曝光证明。
- 需复核：质量、几何、确认、剩余帧数或时间预算没有满足要求。保留原因和原图，不强行报成功。
- 采集失败：SDK采集错误重试耗尽等情况；原始错误/失败调用仍保留。
- 程序或接口错误：独立审计、输入来源或程序异常，不能作为已验收锁定。

关灯ACK仅表示指令被确认；未收到ACK时界面会提示本人查看灯具，不伪填实际熄灭。程序通过OS文件锁避免自身两个采集任务并行，但旧预览/其他软件不遵守这个锁，仍需本人先关闭。

vendor/内38个文件逐字节只读保存；dependencies/内72个依赖另有完整SHA清单。没有修改XDL规则、TJ原文件、正式发布门槛或硬件工程。

新增的是本机来源与mask校验、`.npy`到0/1原始字节的正确转换、中文工作线程界面、实时进度、同位确认、操作程序互斥、退出关灯和ZIP归档。单次采集超时30秒，以覆盖现场首次ROI掩码上传约15秒；每次仍受剩余整轮预算限制。

自检改进版进一步核对02来源的唯一strict实拍记录、样件/参数/完整帧身份、PNG和RGB565的SHA及读回。用同一份内存快照生成定位预览、上传掩码和保存来源，避免确认后另读到了不同文件；定位预览无法显示时禁止开始。切换来源或开始新轮次会清掉旧指标。mask只容许保存多边形角点舍入引起的一个光栅边界像素差，不改变成像质量阈值。

归档先写临时文件，重新解压逐文件核对库存与SHA，验证成功后才发布最终ZIP；已有同名结果不会覆盖。失败保留原始目录并显示路径，不留下假装完成的ZIP。含点号的样件编号完整保留，避免截断文件名。详见SELF_REVIEW.md。

XDL原最大8个模型请求、32帧、40000ms及所有质量门槛保持原值。其模型一请求为3丢弃+1评价=4帧，实物执行还包含1等待帧=5帧；TJ适配器单独按真实请求预留，因此32帧预算不保证允许8次执行。初始化上传、失败、主机处理及未知物理成本单列；不靠扩大预算冒充收敛或收益。

共同区由首个实际新评价帧和显式native mask建立，之后区域冻结。native设备统计与common控制统计分开。已有完整图仅用于几何初始化，不能作为这次控制器的新确认帧。每次调节、确认和回退都重新调用strict采集。

### 对齐XDL 10月15日新报告的区域（r3）

收到新报告后发现：首版/r2直接使用原采集mask，而XDL表格采用冻结`board_mask`函数（多边形光栅化、15×15侵蚀、保存图四像素边界排除）。本版在新的07采集中明确上传该板内mask，SDK及独立审计仍按实际上传的mask重算；本次07的设备native与控制器common分母因此一致。原02～05历史统计、原始mask和照片原样保留，不能拿旧native计数直接对比新07统计。

| 最新固定轮次 | 原采集mask | r3新07上传/评价mask |
| --- | ---: | ---: |
| sample001 | 624567 | 602405 |
| sample002 | 624533 | 602441 |

按已冻结源码在全部24张重复图重算，两板面积和8组灰度/RGB风险均值与XDL报告中的舍入值相符。XDL导出的mask原文件及来源清单尚未收到，未宣称与其数组逐字节对照完成。新的plan.schema=3记录原mask、新mask、生成函数及其SHA；旧审批计划或被修改的mask哈希会在开socket前拒绝。换板时按同函数生成本轮区域，不写死上述面积。裁剪图像范围和9×9保存图滤波不变。

这只是输入区域口径对齐，controller-0.1、阈值、确认/预算规则不变；0.2草案未实现或启用。

## 输出

- `plan.json`、`source_geometry.json`、`native_mask.bin`、`source_full.png`、`source_session.json`、`source_mask.npy`、`source_result.json`：核验后同一份来源快照、参数与hash。`source_mask.npy`保留02的原始mask；`native_mask.bin`是这次07实际上传的板内mask，两者分别记录SHA和面积。
- `captures/`：每次SDK调用的原始RGB565/PNG、读回、诊断、outcome与逐事件trace。
- `loop/`：冻结共同区、native/common指标、状态转换、成本账本、完整回执与SHA。
- `operator_summary.json`：界面结果、锁定档位、停止原因、关灯、异常及独立审计结果；另记预检/来源保存、关灯、审计及归档前主机耗时。
- `output_manifest.json`、同名ZIP及`.zip.sha256`：原文件库存与解压后字节核验。
- `.zip.receipt.json`：ZIP的SHA、大小、归档耗时与从启动到验证ZIP发布的主机总耗时；附件写入本身不计入该时间。它是ZIP外的回执，避免自引用哈希。

TJ原完整审计在运行机器上执行后写入摘要；其中路径绑定为本机绝对路径。跨机器收到ZIP可先验证output_manifest，不能仅更换路径/重签回执冒充重新完成原SDK审计。

H3、完整缺陷定位、LED/增益搜索和自动四方向融合不在首版。外部IO正式资格、真实光学稳定时间、正常真值及检测准确率仍待实测；本程序不自动改为已验收。

## 离线验证与复跑

沿用当前Python3.11环境（路径见07脚本），不需要重新安装现有依赖。跨电脑依赖见requirements.txt，Tk需要带Tk的Python。输出路径必须全新。

```powershell
$py='C:\path\to\python.exe'
$app='C:\path\to\auto_exposure_r3'
& $py -B "$app/auto_exposure_app.py" --lab-root C:/BX72_0105_LAB --plan-only
& $py -B "$app/auto_exposure_app.py" --software-peer --out C:/new_localhost_smoke
& $py -B "$app/verify_operator.py" --lab-root C:/BX72_0105_LAB --out C:/new_operator_verification
& $py -B "$app/vendor/TJ/work/pc_closed_loop_20261015/run_verification.py" --dependencies "$app/dependencies" --work C:/new_tj47_verification
& $py -B "$app/replay_saved_frames.py" --dataset C:/path/to/repositioned_two_specimens_1720_1742 --out C:/new_saved_replay
```

首版完成TJ47项、操作程序16项及两板保存图策略回放，证据在verification/。本次自检将操作程序回归扩到30项，重新覆盖隐藏Tk响应/停止、完整尺寸ROI经localhost走正式编排、来源身份与快照、预览失败门控、压缩故障及恢复，明确physical_board_used=false。首版证据与本次失败后修正测试断言的记录分开保留，最终报告见verification/review_operator/。冻结的TJ47项未因本次封装改动重复运行。

r3另扩到32项，最终报告在`verification/aligned_operator/`，覆盖两板XDL区域生成、完整链路的新设备统计/旧来源mask区分和旧计划拒绝。`verification/aligned_saved_replay/`是按r3板内区域的新离线回放，两板仍各消费600行两张后锁定；原回放和r2证据另保留，避免混用区域或覆盖历史结论。

两板保存图池均消费600行R1、R2后离线LOCKED；只消费各2张，未宣称24张都进入策略，也未选择全局最优。`replay_saved_frames.py`标为离线反事实回放，原实际扫描400→500→600→700及原成本不改写。尚未由本人运行真实板卡自动闭环。
