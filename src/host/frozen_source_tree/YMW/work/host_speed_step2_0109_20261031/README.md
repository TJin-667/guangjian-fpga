## 做了什么

原工程采集执行器已经在`_off_rows`保留八帧的`residual_n`和`valid`，并用于核对板端最终融合。本步把这些审计产物交给后处理，避免重新计算质量和局部残差。

- [intermediates.py](intermediates.py)：严格SDK生产者接口、离线重建接口、来源绑定、无损写入与恢复。残差保留int16，质量逐bit保存，未量化或降采样。
- [reuse_context.py](reuse_context.py)：继续解码实际PL R32，核对所选帧的有效性、灰度、残差及unknown，用复用数组建立原冻结上下文。
- [PLAN.md](PLAN.md)：完整数据流、范围、性能区间与下一步接入要求。

缓存绑定group/digest、八帧完整身份、每帧实际参数、ROI、mask、原片、载荷、原始metadata、R32和参考源码。不完整采集、串组、数据或来源变化明确拒绝。它是本机受控流程的完整性缓存，不是签名，也不能把外来NPZ当成已核验产物。

冻结组合`f09eb5885e1d`、阈值、弱段增强和复检规则均未改动。现用0109资格源码、SDK、RTL、bit及窗口保持原样。本候选只增加主机数据复用，不改变PL/PC算法职责。

**这些八帧残差来自当前工程路径已有的PC镜像审计，不是从FPGA额外取回八套残差。** 本步保留该审计并复用其产物，没有为了缓存新增一轮完整PC H2计算。若后续另行减少PC镜像审计，这个复用前提也会改变，需要回到第一步按需访问或评估新的板端证据接口；不能把“取消镜像审计”与“继续复用其数组”的节省同时计入。

## 收益为什么还有限

本轮原上下文构建中位数约1.59～1.67秒，复用后的R32上下文约0.42～0.44秒。但独立交接文件的创建/核验约0.66～0.70秒，读取/核验约0.63～0.67秒，抵消了部分节省。分段均为包含内部工作的独立中位数，不应简单相加替代总区间。

下一步应把派生字段合并进已有原生证据缓存，减少对同一来源的重复核验。不能通过关闭CRC、身份、参数或错误保护提速。当前独立交接文件每组12,690,958字节，约12.10MiB；复用的残差/质量数组合计17,915,904字节，约17.09MiB，不是整个进程内存峰值。消耗的是主机RAM和E盘派生存储，不增加FPGA BRAM。
