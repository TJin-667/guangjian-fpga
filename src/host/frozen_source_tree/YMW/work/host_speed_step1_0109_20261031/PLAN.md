# 0109提速第一步：原生残差坐标访问复用

2026-10-31。用户要求逐步推进。先进行只读软件试验，不烧录、不采集、不改网络、不切换现用入口。

## 目标与范围

缩短PL返回R32之后的主机延续处理。保持冻结组合`f09eb5885e1d`、全部十项检测数组、完整复检证据与评分精确一致。八张原片、来源和全部图文导出仍然保留。

本步不修改冻结算法、资格源码`final_board_0109_20261030`、既有性能程序、SDK、RTL或bit。缓存只使用主机RAM，不增加FPGA资源，也没有将完整9×9残差重新搬回PC预计算。

## 原因与实现

同一条复检采样路径会按八帧、亮暗两种极性反复访问相同的整数坐标。原访问器每次都进行坐标分组和tile内索引构造。

新增`PlannedResidualAccess`继承原`ResidualAccess`的精确tile计算和LRU管理，只复用：

1. 最近一组坐标的tile分组及局部下标，跨八张图复用。
2. 该坐标组在每一帧的已取值结果，避免亮暗极性检查重复取值。

坐标缓存比较数组内容，不能只比较对象身份，防止调用者原位修改索引导致错误。每次返回独立可写数组，防止调用者修改返回值污染缓存。变换坐标后立即失效，只保留一组坐标计划。旧64像素tile和256项LRU上限保持。

适配器调用原混合上下文构造和全部R32、质量、来源灰度检查后，替换该上下文的残差访问对象。没有改任何共享模块或冻结源码。

## 验证顺序

- 自检：独立密集H2参考、REFLECT101四边、跨tile/广播/标量/空索引、坐标原位修改、返回值修改、LRU逐出、输入灰度别名与非法索引拒绝。
- 试跑：相同已保存八帧和R32，原访问器与新版交替各三次，计时上下文加冻结计算；每次计时后比对实际保存的十数组、完整复检JSON及评分身份。
- 完整导出：独立原片组上交替各三次，使用原`Tools.export`及原冻结导出函数，包含图像、报告和压缩数组；同样逐次核对正式结果。
- 原数据封印、冻结依赖和原性能程序在前后分别验证。性能采集产生的新鲜A/B帧不互当相同输入；本步只在各自相同原片内配对。

`cProfile`只用于定位调用开销，包含剖析器影响，不直接作为提速比。正式对照不启用剖析器，均单线程OpenCV，每个方法独立重建上下文和缓存；加载、独立证明和输入哈希不计入处理区间。
