# 0109 独立候选使用与一次性验收

这是与0109位流匹配的独立入口。0108原程序和位流保留；0108运行时请继续用原入口。程序不会替你下载bit或更改Cisco/网卡。

1. 等独立发布收据明确bit已生成，正常停止并关闭采集/预览窗口，再在Vivado选择收据中的0109 `.bit`下载。仅供电不代表SRAM中已经有新bit。
2. 启动`RUN_0109_SYSTEM.cmd`。样品名可自己填，默认400/800行、1倍增益、LED128；改曝光前保证低<高且都在1～1116行。正式方案仍用400/800。
3. 工件已经移动时，先手动调焦，再点“重新定位”，确认工件四角与留边像素。仅裁剪，不取正。预览目标2帧/秒、最多1000帧；鼠标拖框选调焦区，滚轮/拖动查看细节，左右画面来自同一帧。
4. 同一摆放已有PLAN，可直接选择为ROI模板，无需重新定位。旧0108 PLAN仅复用几何和mask，新入口会生成新的0109计划/摘要/组ID，不改旧计划，不把旧图当新采集。摆放是否需要更新由操作者判断。
5. 点“采集下一组”。每组另有1张ROI执行域准备帧，不属于正式8帧；正式8帧为CH1～4低/高各1张。各帧实际曝光、增益、灯、身份、CRC和计数均核验；失败保留记录并结束会话。
6. 完成后看最终检测/复检、八原片目录及性能分段记录。黄色为冻结正式检测，橙框是建议复检，不自动判合格；分数不是正确概率。性能报告另有“器件分段计数”链接，逐帧显示三个本域阶段。
7. 工件/相机/灯位没动，可直接改组信息或人工曝光拍下一组。同ROI/mask/格式且保留同一受控会话时，后组不重新上传mask。调焦、重新定位、结束会话或关闭窗口会释放会话；ROI/mask/格式变化须重新配置。

## 需要操作者加入的最小窗口

候选生成、自检和配套软件准备完成前无需采集。完成后集中做：

- 一次下载**本版0109**；用现有开发板材003/004/005任意一块，不制作新划痕。
- 同一窗口、同摆放、同格式49连续两组：第一组400/800，第二组可用300/700验证人工配置，之后恢复正式400/800。检查实际相机读回、24页计数、数学零差、OFF回复及第二组mask=0。两组是接口工程验收，不能当成独立验证板或曝光优选证据。
- 若安排本版共同复位核验，单独运行`RUN_RESET_0109.cmd`，按脚本提示按KEY2一次；它只用小ROI建立旧身份并恢复8帧，不会下载位流。旧0108已做的复位记录保留，但不冒称新0109实板通过。

将完成后的结果路径发回核验即可。软件不会读回FPGA里完整bit的SHA，因此实际下载文件与操作者确认仍须保留；不能只凭版本号宣称bit字节已读回验证。外部IO完整签核、完整公平端到端加速比仍按缺项列报。

## 同输入性能工具

新的真实组通过后，可运行`measure_same_input.py --source 本组fusion目录 --out 新E盘目录`，默认3次PC RAM参考，比较精确H2与仅MaxAbs/R32阶段，逐字核对实际R32，列出同组24页器件服务计数。程序只读原片，不采集、不改阈值。PC的质量计算单列，scratch单列，不能把重叠阶段相加；阶段比值不是完整系统加速比。软件模拟输入只有显式`--allow-fixture`才允许读取，并强制不输出硬件比值。
