# GRAY8 + SAT1：独立实验编码与交接

启动日期2026-10-25，最新分工r2。用户授权六七天内闭环，先做路线一；原TJ任务本轮由YMW接手，助手协助RTL/仿真/资源/SDK，YMW本人负责全部现场采集/烧写，XDL负责算法/训练。本轮不依赖TJ。本目录是新实验代码，不替换现用09、SDK、安装或0105 bit。

## 当前实现边界

- `codec.py`：灰度+逐像素RGB饱和标志编解码、严格离线分包重组、GRAY/SAT重建现用tile质量。仅离线工具，不打开socket，不调用板卡。
- `gray_sat_encoder.v`：可暂停的流式RTL编码原语，使用少量流水寄存器和8像素组，不申请整帧BRAM。按现用整数灰度计算，输入RGB565不改变。
- `tb_gray_sat.sv` / `test_codec.py` / `verify.py`：颜色码、字节黄金值、异常分支、历史实图与RTL仿真；`synth_encoder.tcl`仅综合/布局布线该原语，不生成整板bit。
- 尚未集成整板发送器、能力协商、payload CRC64、严格SDK、新8帧固定采集入口，也尚未验证新融合质量。不得把本目录称为可上板版本。

## 实验负载格式v0.1

每8像素：依次8个gray8字节，再1个SAT字节；SAT bit7对应第一个像素。最后不足8像素时发送k个gray字节再1个SAT字节，SAT低位补0。顺序为保存ROI行优先，组可以跨行，UDP边界可以跨组。总字节数 `N + ceil(N/8)`。

SAT=RGB565的R5==31或G6==63或B5==31。灰度按现用RGB位复制及9798/19235/3735整数系数计算。不得改成近似系数、先截位的平均灰度或强制丢掉SAT。

离线包沿用20字节LGHT应用头布局，实验format=0x31、1380字节最大负载，仅供接口对齐。旧format=1保持严格拒绝新编码。format/固件能力由TJ结合现有枚举确认；当前0105不支持这个模式。

离线Receiver要求预先已知SHA后才能返回完整数组。**SHA是历史回放凭证，不要求FPGA计算SHA。** 未来板端必须对真实新负载计算/发布CRC64，并将格式、字节数、请求/session/frame身份、相机/ROI代际、读回和完整H1/H2分析结果绑定，SDK最后确认后才能发布。16位frame_id和内容哈希本身不构成完整采集来源。

发送链必须保留完整排空、最终提交、失败/取消/背压规则；原语的done仅表示编码结束，不等于整个采集成功或H1/H2成功。输出在整次验证完成前都是临时数据。

## 执行顺序

1. YMW助手已完成编码/离线合同及原语黄金样例；接着由YMW侧集成RTL发送分支、协议/CRC并检查资源/时序，现场硬件操作仍由本人完成。
2. XDL不等新bit，用现有RGB解出的灰度/SAT推进固定1倍低高曝光融合；确认是否还需要颜色通道。先少量试采选固定值，再成批标注训练。
3. YMW助手适配新格式SDK/归档和固定四向双曝光入口；正式图预算8张，不沿用旧4+2补拍预算。不运行自适应寻曝。
4. 整板离线门槛通过后，给YMW最小上板清单。先验证测试图或同一冻结帧的双格式结果，再真实相机。不同时间新拍两帧不能要求逐像素相等。
5. 新bit与旧0105、09并存；只有新链路和质量验证通过才纳入实验闭环。

按用户最新六七天完成整个闭环的要求，内部目标10/30冻结融合及系统，10/31完成正式视频和材料；11/1仅作额外提交缓冲，不作为闭环完成前提。官方提交要求另核。BRAM硬预算80%（108个36Kb等效块），现有81.5块，新整板仍需实测；OOC原语资源不能直接加到整板当作新实测值。

详细并行任务见`HANDOFF_TO_YMW_FPGA.txt`、`HANDOFF_TO_XDL.txt`及`MEETING_ROUTE_CONFIRMATION.md`。`HANDOFF_TO_TJ.txt`仅历史，不是当前分工。测试命令：使用现有Python环境运行 `python -B -m unittest -v test_codec`；完整verify需本机冻结算法、原包和Vivado2018.3路径，输出目录不得已存在。

## 2026-10-25第一批验证结果

- 7项编码/重组测试及2项固定8请求计划测试通过；软件与RTL均覆盖65536种RGB565颜色码。
- 10个既有ZIP中24个RGB图像成员复算一致；其中8份是归档副本，实际为16份不同灰度/SAT输入，不算24次独立采集。gray、H2、valid、weak、strong、连接候选、SAT及tile质量均一致。此证明编码/预处理等价，不证明尚未交付的新融合质量。
- `verification/run_04`为最终流水版的RTL仿真与图像回放凭证；包含随机式确定暂停、尾组、取消、错误EOF及活动事务重启拒绝。旧run_01/02是仿真timescale配置失败记录，run_03是加流水前功能通过记录，不覆盖旧记录。
- `verification/ooc_02`：原语独立布局布线为290 LUT、219 FF、0 BRAM、0 DSP。125MHz下寄存器到寄存器setup +1.841ns、hold +0.202ns。
- **不能声称OOC全时序通过**：带假定端口延迟的汇总WNS +0.881ns、WHS -0.219ns；工具明确提示OOC无HD.PARTPIN_LOCS，端口路径分析不准确。端口hold仍是YMW侧集成待办，不用假路径隐藏，需在真实发送器上下文和整板约束下闭合；本结果不是整板准入。
- 现用35个关键文件与接手快照一致，已跟踪仓库文件无改动。只有两个独立实验目录未跟踪，不合并、不覆盖安装、不烧写。

`fixed_plan.py`生成可审阅的四向低/高8请求清单，不执行采集；400/800只是可选参数，须由XDL少量开发数据定值后冻结。未确认曝光、来源/姿态锁、严格SDK、新格式能力、最终提交前不能直接运行。

纯RTL重跑可用Vivado2018.3在含黄金HEX文件的工作目录中依次运行：`xvlog -sv gray_sat_encoder.v tb_gray_sat.sv`、`xelab tb_gray_sat -s gray_sat_sim`、`xsim gray_sat_sim -runall`。源码与HEX路径按实际位置指定即可，无需板卡。
